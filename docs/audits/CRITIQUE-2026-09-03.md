## 1. Verdict

The OS *looks* haunted and mostly *navigates* well, but several features are **façades**: present, styled, copy written — with no implementation behind them. The pattern across the worst findings is identical: *the words promise an interaction the code never built.* Layered on top is a three-generation documentation stack whose newer decisions (persona themes, sea-scoped `extc`, bury-only trash) were implemented while older promises (material themes, `extc` anywhere, dig-and-re-add graveyard, sea release ritual) were left standing in shipped UI copy and in the covenant.

## 2. Critical — promised features that don't exist or trap the user

### C1. The Sea's release ritual was never implemented — the app is a decorative meter
- **Evidence:** `src/features/sea/sea.js` (85 lines total) implements only: a `mousemove`-driven depth gauge (lines 11–25), CSS breath rings, the `extc` listener, and exit/help wiring. `sea.html:59` asks *"what do you carry to the deep?"* but the page contains **zero** `<input>`/`<textarea>`/`contenteditable` and no other interactive element (live probe: `inputs: []`, 98 DOM nodes total). `state.sea` stays `[]` forever.
- **Against spec:** Covenant Truth #8: *"One line of text: 'What do you want to release?' … 2s fade, 4s breath, then release. The first 800ms are uninterruptible. Intensity (1–5) changes breath amplitude."* None of that exists — no input, no release, no intensity, no pacing rules. The app's entire purpose is the ritual; what shipped is a mouse-follow bar.
- **User experience:** a question that cannot be answered. The machine asks; the machine cannot hear.
- **Fix direction:** decide — either implement the ritual (input → breath sequence → release → `state.sea`) or change the copy to not promise one.

### C2. Trash ("Artifact Graveyard") promises dig-and-re-add; it is a bulk permanent-delete utility
- **Evidence:** the mandated copy (`currentliberplans.md` §4) *"— click to dig for deleted artifacts, then click to re-add —"* is shipped in `trash.html`, but `src/features/trash/trash.js` implements only four bulk actions; `commitBurySigils()` (lines 38–43) is literally `state.set({ sigils: [] })`. There is **no graveyard storage anywhere** (`src/state.js` has no `buried`/`graveyard` key), so nothing dug up can ever exist. Covenant O.3's 7-day fade mechanic: absent.
- **Aggravator — inverted confirm semantics:** the app reuses the save-prompt chrome every other app trains as *"keep it?"* (keep = preserve the artifact). Here **"keep" executes the destruction** and "discard" cancels (`trash.js:149–157`). Muscle memory from divination/games ("keep" the card you drew) now deletes all sigils.
- **Against spec:** PLAN-CHANGES E2 only ever specified bury buttons — the dig/re-add copy was written anyway, contradicting the implementation it was shipped with.
- **Fix direction:** either implement the graveyard (append buried items to a state key with timestamps, render dig list, re-add) or rewrite the copy to match reality — and give the destructive confirm distinct labels ("bury it" / "not yet"), not keep/discard.

### C3. `extc` "anywhere" is false — the shadow layer is unreachable by its advertised path
- **Evidence:** `settings.html:55` and `desktop.html:114` both instruct *"type `extc` anywhere to toggle the overdrive."* The only listener in the codebase is scoped to the Sea page (`src/features/sea/sea.js:52–67`; `src/shadow.js:3` confirms the global listener was removed). Live test: typing `extc` on `desktop.html` → no class change, `shadowOn` stays `false`, no prompt.
- **Context:** PLAN-CHANGES G1 *deliberately* scoped it to sea.html — but the two UI surfaces teaching the old contract were never updated. Covenant Truth #10 and items P.1–P.4 (full static, red dust, solid LED, flicker, chromatic aberration) are therefore effectively dark feature work.
- **Fix direction:** one-line copy change in two files — or restore a global listener if "anywhere" is the intended contract.

### C4. The tutorial's final beat leaves a dead, clickable-looking button in a fading window
- **Evidence:** `src/wanderlust.js:186–191` — when a final-fork reply ("i arise." / "i will.") is clicked, `finishScript()` runs (sets `tutorialDone`, `close()`s the window) **without clearing the reply buttons**. The window fades (`.wanderlust-window` observed at `opacity:0; pointer-events:none`) with the button still rendered inside it. Live repro: the button stays visible-but-unclickable; clicks at its coordinates hit `#desktop` (elementFromPoint verification); a second attempt times out because the desktop intercepts.
- **Why it matters:** this is the single most important narrative beat of the OS ("I arise the same but different."). The user's last visible affordance is a button that does nothing. It also *looks* like a bug to anyone who double-clicks.
- **Fix direction:** `clearReplies()` before `close()` in `finishScript()`.

### C5. The 12 carvings never glow — covenant centerpiece wired in CSS only
- **Evidence:** `.carving.active` styling exists (`styles/bezel.css:65–70`), but no JavaScript anywhere applies `active` to a carving on theme change (grep across `src/`: zero hits). Live check after switching to the whimsy theme: zero carvings carry a glow/active class.
- **Against spec:** Covenant Truth #3 ("When a visitor's theme is active, their carving glows") and A.2. The theme system itself works (`theme-whimsy` verified on the machine element, persisted cross-page) — the bezel-side consequence was simply never wired.
- **Fix direction:** in the theme-apply path, map `state.theme` → the matching carving and toggle `.active`.

## 3. Major — working, but poorly

### M1. Developer spec text is shipped inside "Raison" panels (systemic)
- `games.html:64`: *"input: click a booth to open its stage. output: a game artifact is appended to state.games and a result entry is appended to state.satchel on stage close. booths: …"*
- `themes.html` raison panel: *"…options: corrupted, clean, shadow, mono, gold…"* — which is also **factually stale**: the shipped theme list is corrupted + 12 personas (verified: 13 `.themes-tile-name`s).
- `sea.html:49–50`: *"input: mouse movement within the deep. output: the depth gauge fill animates between 20% and 100%…"*
- Raison is supposed to be an in-character interjector. Instead the "?" help opens internal implementation notes with `state.*` vocabulary — and in themes' case, a spec that no longer matches the product. Covenant rule 7 bans placeholder text; leaked dev notes are worse.

### M2. Games: 4 of 13 booths are unreachable at the project's own verification size
- The booth grid is taller than the fixed CRT stage; **no scroll container exists** (probe: page not scrollable, no inner scroller found), and the bottom row (thermometer, mandala, cut-up desk, mindful color) is additionally **click-blocked by the decorative `.games-bulbs-bottom` strip** (elementFromPoint at booth center returns the bulb strip, not the booth; booth spans y 518–671 at 1280×800).
- Result: five booths are effectively decorative — you can see the top sliver of their cards and never open them.
- Fix direction: make the stage scrollable (or shrink tiles), and `pointer-events: none` the bulb strips.

### M3. I Ching: the cast button never advances past "cast line 1"
- Verified across all six casts: the label read "cast line 1" every time (screenshot after completion still shows it). The hexagram, name lookup ("Before Completion"), interpretation, and `state.iching` write all work — the progress affordance is dead, and there is no completed/disabled state after line 6 (an eager 7th click's behavior is undefined).
- Also: the header instruction *"Type a question & click a card for an interpretation."* (tarot-mode copy, per the text-replacement table) persists in I Ching mode, where the interaction is cast, not click.

### M4. `aria-hidden` used as a visibility mechanism traps focus
- Browser console warning, reproduced twice: *"Blocked aria-hidden on an element because its descendant retained focus… Consider using the inert attribute instead"* (`wanderlust-window` with a focused `.wanderlust-reply`). Every app window toggles `aria-hidden` for show/hide (settings modal, artifact menu, save prompts). Any focused element inside makes the subtree invisible to assistive tech while remaining interactive — violating the project's own "Agency over protection" rule.
- Fix direction: swap `aria-hidden` toggling for the `inert` attribute (it blocks focus *and* interaction).

### M5. Documentation stack contradicts itself — and the UI ships the contradictions
Three generations of intent coexist, and each pair disagrees somewhere:

| Topic | CRITIQUES.md (oldest) | PLAN-CHANGES / currentliberplans (newest) | Shipped UI |
|---|---|---|---|
| Themes | 12 **materials** (verdigris, foxing, kelp…) — "NON-NEGOTIABLE" | 12 **persona palettes** (K1) | persona palettes ✓ + stale "clean/shadow/mono/gold" text in raison panel ✗ |
| Personas per app | Satchel=Mad Scribe, Learn=Librarian, Cohort=E-Lizabeth, Themes=Riason's prison | Satchel=librarian, Learn=mad scribe, Cohort=raving pete, Themes=iris mappa, Relation=e-lizabeth | follows newest ✓, covenant never marked superseded |
| extc scope | "typing `extc` **or** the shadow app" (global) | sea-scoped only (G1) | sea-scoped code ✓ + "anywhere" copy in two files ✗ |
| Trash | 7-day fade mechanic (O.3) | bury-only buttons (E2) | bury-only code ✓ + dig/re-add copy ✗ |
| File layout | `loadFeature.js` loads each feature | — | no `loadFeature.js` exists anywhere in the tree |

- AGENTS.md still instructs builders to re-read "sections A–S, 39 ❌ items" as "the single source of truth," but at least 14 of those ❌ items are now deliberately obsolete (resolved differently or superseded by PLAN-CHANGES) — e.g. B.4's white status line, N.1–N.4's prison/materials themes. Nobody can onboard from the covenant without building the wrong thing.
- Fix direction: one "superseded-by" banner per section in CRITIQUES.md (or delete it in favor of currentliberplans.md), and purge the three stale raison-panel texts.

## 5. What is genuinely well implemented (for contrast)

- **Dial navigation** — clean 3-position carousel, verified cycling through all apps and opening on click.
- **Divination's dual-mode core** — tarot draw → draft state → keep/discard → persisted artifact; I Ching question → 6 casts → correct hexagram lookup → interpretation → `state.iching`. The logic is sound; only its affordances lag (M3).
- **Theme system** — 13 persona palettes, `theme-*` class application and persistence verified cross-page; Wanderlust's one-line opinions are present and in-voice.
- **Status line** — cycles on the 12s interval with covenant-voiced messages.
- **State layer** — `Object.assign` merge semantics in `set()` (patch, not replace), pub/sub, single `liber_vacui_v1` key.
- **Smoke suite** — 25 steps covering the sigil → constellation → relation happy path; green.
- **No-shared-CSS covenant holds** at the file level — every app stylesheet is unique (no cloned files), and the dissonance between apps reads visually.
- **Page health** — zero console errors across all 14 pages.
